# Pipeline Ordering — Regression Tests — v0.4.3

6 required scenarios, all **EXECUTED** (real Python assertions this session), using the same

### 1. Retracted article retrieved → gate → excluded before DEL-7

**EXECUTED.** Parsed a schema-correct PubMed record with `PublicationType: Retracted
Publication`, ran it through `apply_retraction_gate()`. Confirmed it lands in `excluded` with
`exclusion_reason: "RETRACTED — EXCLUDED FROM SYNTHESIS"`, and is absent from `included` — the
only pool eligible to proceed to step 7 (study classification) and step 8 (DEL-7 tagging) in the
corrected `SKILL.md` workflow. Since the record never reaches `included`, it structurally cannot
receive a DEL-7 supporting-evidence tag through this pipeline.

### 2. Retraction notice → flagged before classification

**EXECUTED.** Parsed a record with `RefType="RetractionOf"` (`record_role: "retraction_notice"`),
ran it through the gate. Confirmed it lands in `flagged` with
`flag_reason: "RETRACTION NOTICE — CONTEXTUAL ONLY, NOT CLINICAL SUPPORTING EVIDENCE"`, and is
absent from `included` — never reaches step 7's classification pool.

### 3. Clean article → passes gate → classified

**EXECUTED.** Parsed an ordinary record with no retraction/correction signal, ran it through the
gate. Confirmed it lands in `included` — eligible to proceed to step 7 (classification) in the
corrected workflow.

### 4. Expression-of-concern article → flagged before synthesis

**EXECUTED.** Parsed a record with an `ExpressionOfConcernIn` notice (not itself retracted or
corrected), ran it through the gate. Confirmed it lands in `flagged` with
`flag_reason: "EXPRESSION OF CONCERN — USE WITH HEIGHTENED CAUTION"` — distinct from
`REASON_RETRACTED`, confirming expression of concern is never treated as equivalent to
retraction — and is absent from `included`, meaning it cannot reach step 13 (synthesis) as
ordinary evidence.

### 5. Corrected article, unresolved → stopped/flagged before synthesis

**EXECUTED.** Parsed a record with an `ErratumIn` notice (`is_corrected: True`), ran it through
the gate with no resolver supplied (the conservative default). Confirmed it lands in `flagged`
with `flag_reason: "CORRECTION EXISTS — VERIFY CURRENT VERSION"` and is absent from `included` —
stopped before it could reach synthesis as an unqualified, unresolved-correction citation.

### 6. Workflow-order static test confirms retraction gate precedes study classification in
SKILL.md

**EXECUTED.** A Python script parsed `skills/evidence-research/SKILL.md`'s `## Workflow` section,
extracted every numbered step's title, and confirmed programmatically:
- The retraction-gate step's number is lower than both the study-design-classification step's
  number and the DEL-7-tagging step's number (5 < 7, 5 < 8).
- No sub-numbered step (e.g. the old `"7a."`) remains in the active workflow list.
- No stale "before step 4" contradiction remains in the active workflow list (the exact defect
  this patch fixes — see `PIPELINE_ORDERING_AUDIT.md`).
- The step numbers are exactly 1 through 16, strictly increasing, with no gaps or duplicates.

This test caught a real leftover during this patch's own development: an early draft of the
corrected `SKILL.md` still contained the literal string `"7a"` — in an explanatory sentence
describing the *old*, now-fixed numbering, not a live contradiction, but the first version of
this test flagged it anyway because it checked the whole file rather than scoping to the active
`## Workflow` section. The test was corrected to isolate the workflow section specifically before
being reported as passing — disclosed here because a test that has to be adjusted after an
initial failure is worth being honest about, not quietly rewritten and re-run without comment.
