**Executed. PASS (both connectors).** PubMed: constructed a record with a `CommentsCorrections`

### 10. PubMed/Crossref exact match → VERIFIED
**Executed. PASS.** Ran `citation_verifier.verify_citation()` on the real Smielak et al.
bibliographic data, represented once in PubMed-shaped form (double-space title quirk,
abbreviated journal, online-first year) and once in Crossref-shaped form (issue year, full
journal name). Result: `status: VERIFIED`, all 4 comparable fields matched.

### 11. DOI mismatch → IDENTIFIER_MISMATCH
**Executed. PASS.** Two records with different DOIs (`10.1/aaa` vs `10.1/bbb`) but the same
title. Confirmed `verify_citation()` returns `IDENTIFIER_MISMATCH`, not `UNVERIFIED` — DOI
disagreement is treated as the strongest, most explicit kind of conflict, checked before the
softer field-by-field comparison.

### 12. Substantive title mismatch → UNVERIFIED
**Executed. PASS.** Two records with genuinely different titles (matching author/journal/year).
Confirmed `verify_citation()` returns `UNVERIFIED` with the specific title mismatch named in
`mismatch_reasons`.

### 13. Online-first year ±1 legitimate match
**Executed. PASS.** Two otherwise-identical records differing only by publication year 2021 vs
2022 (the documented online-first-vs-issue-date tolerance). Confirmed `verify_citation()` still
returns `VERIFIED` — the tolerance is applied, not penalized.

### 14. Same DOI but conflicting metadata → conflict, not silent merge
**Executed. PASS (both required variants).** (a) Same DOI, substantively different titles →
`deduplicate()` returns both records unmerged with a `FLAGGED_CONFLICT` log entry naming both
titles. (b) Same PMID, different DOIs → the cross-check pass (which specifically exists to catch
this case, since same-PMID-different-DOI records land in separate DOI-keyed groups and would
never otherwise be compared) returns both records unmerged with a `FLAGGED_CONFLICT` log entry
naming both conflicting DOIs.

### 15. Rate limiter spacing test using mocked clock
**Executed. PASS.** Used a fully mocked monotonic clock and mocked sleep function (no real time
elapsed, no real waiting) — confirmed `SpacingRateLimiter` never permits two calls with zero
elapsed wall-clock time to both proceed instantly (each after the first waits the full `1/rate`
interval), and confirmed it does NOT over-throttle when enough real time has already elapsed.
This directly demonstrates the fix to the v0.4 token-bucket burst issue.
